💥 Moves

Rebalance any move’s FP cost and damage.

How does this work?

Every move in the game lives in one data file (etc/attack_defs). A move is one or more hits; each hit has an FP cost and a damage value (damage is base power — the game scales it by the attacker’s Attack stat and rank; status-only moves have damage 0). The total row is what the game displays and charges — it’s kept in sync automatically. If a move inflicts a status effect, you can change its chance.

Element: in Fossil Fighters a move has no element of its own — it always uses the element of the vivosaur that knows it. To change that, edit the vivosaur’s element in the Vivosaurs tab.

⛏️ Dig Sites

Control exactly which fossils each dig site hands out.

How does this work?

Each dig site rolls the fossil you find from a table of “rock records”. Every record below is one entry in that table: pick which vivosaur and which body part (head, body, arms, legs) it should give. Records are equally-weighted rolls, so the share column is that record’s chance of being your find. Jewel rocks, droppings and dark fossils are shown locked — they’re special items, not vivosaur fossils.

Select a dig site on the left to see its rock records.

⚔️ Battles

Redesign every fight in the game, slot by slot.

How does this work?

Each battle file lists the teams. For every fighter slot you can set the vivosaur, its rank (1–20), a stat multiplier (×1.0 = unchanged, higher = stronger), and a tactic class (1–4, how aggressively that vivosaur is played). The four AI tactic ids (1–17) control the enemy’s overall strategy — 11 and up is the smarter late-game set. Player-side entries are shown for context.

Select a battle on the left to edit its teams.

💬 Text

Rewrite any line of text in the game — dialogue, names, menus, subtitles.

How does this work?

The game’s text lives in two kinds of archives: msg/… files hold story dialogue and cutscene subtitles, text/… files hold names and UI strings (vivosaur names, move names, menus). Pick an archive (or search across all of them), edit any string, and save. Formatting codes you’ll see: \n-style line breaks are real newlines, $p is the player’s name, $c1…$c0 colors text, $f starts a new page. Keep lines roughly the original length — the game doesn’t re-wrap text.

🎲 Randomizer & Hard Mode

Optional game-wide mods applied automatically when you build.

Randomizer

Shuffles the game when you build. The seed makes it repeatable — the same seed always produces the same shuffle, so you can share a seed with friends.

Hard Mode

Raises enemy ranks (+2, capped at 20), upgrades enemy AI to the late-game tactic set, and bumps tactic classes in every non-tutorial battle.

Bug fix: elemental resistance

In the retail game an elemental disadvantage does nothing — Fire hits Water for full damage (FF1 applied ×0.75). The game actually ships a dedicated disadvantage multiplier slot in its battle constants… set to ×1.0. This fix writes FF1’s ×0.75 into it, so every matchup counts on every attack: advantage ×1.5 · neutral ×1.0 · disadvantage ×0.75.

One constant, applied at build time only — abilities, Elemental Boost, and everything else stay untouched, and turning the toggle off restores retail behavior on the next build.

📦 Build & Share

Turn your edits into a playable ROM and a shareable patch.

ROM vs. patch — which do I share?

Build ROM produces a playable .nds file for testing in an emulator (melonDS, DeSmuME) or on a flashcart. Never upload the ROM — it contains Nintendo’s copyrighted game.

Create patch produces a small .bps file containing only your changes. That’s the standard, legal way to share a hack: players apply it to their own game dump with any BPS patcher (e.g. Rom Patcher JS). Every patch is verified byte-for-byte before it’s saved.
